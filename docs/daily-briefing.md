# Daily Briefing

A morning email summary of your day ahead — open tasks, calendar events, reminders, and stale contacts — delivered automatically to your inbox at a configurable time.

---

## How It Works

Every morning, a scheduled job generates a personalised summary using the AI provider of your choice and sends it via email. The briefing includes:

- **Open tasks** — your pending to-dos, sorted by priority
- **Today's calendar events** — from Google Calendar (if connected)
- **Upcoming reminders** — reminders due in the next 24 hours
- **Stale contacts** — people you haven't spoken to in a while (if Personal CRM is active)
- **Recent conversations** — a quick recap of yesterday's assistant interactions (if enabled)

## Setup

### 1. Enable the Scheduler

The scheduler container must be running. In the standard Docker Compose setup it starts automatically:

```bash
docker compose up -d scheduler
```

Verify it's running:

```bash
docker compose ps scheduler
```

If the scheduler is not running, the daily briefing will never trigger. The scheduler processes the `schedule:run` command every minute via `php artisan schedule:work`.

### 2. Configure Email

The briefing is delivered via email, so you need working SMTP settings in `.env`:

```env
MAIL_MAILER=smtp
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=your@email.com
MAIL_PASSWORD=your-app-password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=your@email.com
MAIL_FROM_NAME="aiPal Daily Briefing"
```

For Gmail, use an [App Password](https://support.google.com/accounts/answer/185833) (requires 2FA enabled).

### 3. Set Your Time & Timezone

Configure the delivery time and timezone in `.env`:

```env
DAILY_BRIEFING_TIME=08:00
DAILY_BRIEFING_TIMEZONE=America/New_York
```

| Variable | Default | Description |
|----------|---------|-------------|
| `DAILY_BRIEFING_TIME` | `08:00` | Time of day to send the briefing (24h format) |
| `DAILY_BRIEFING_TIMEZONE` | `UTC` | Your local timezone (PHP-supported, e.g. `Europe/London`) |

### 4. Select an AI Provider

By default, the briefing uses your main chat provider. You can set a dedicated provider and model:

```env
DAILY_BRIEFING_PROVIDER=anthropic
DAILY_BRIEFING_MODEL=claude-sonnet-4-6
```

If left blank, these fall back to `AI_DEFAULT_PROVIDER` and that provider's default model.

| Compatible providers | Notes |
|----------------------|-------|
| `anthropic`, `openai`, `deepseek`, `xai`, `gemini`, `ollama` | All chat-capable providers work |

### 5. Rebuild the Container

After changing any `.env` values:

```bash
docker compose up -d --build
```

## Customising the Briefing Content

The briefing is generated by an AI prompt that can be customised. In the admin dashboard, navigate to **Settings → Daily Briefing** to toggle which sections are included:

| Section | Toggle | Description |
|---------|--------|-------------|
| Open Tasks | ✅ On by default | List pending tasks sorted by priority |
| Calendar Events | ✅ On by default | Today's events (requires Google Calendar connection) |
| Upcoming Reminders | ✅ On by default | Reminders due within 24h |
| Stale Contacts | ❌ Off by default | People with no contact in 30+ days |
| Conversation Recap | ❌ Off by default | Brief summary of recent assistant chats |

> The "Stale Contacts" section requires the Personal CRM to be set up and have data.

## Per-User Configuration

Each user can configure their own briefing preferences. In the web UI, go to **Settings → Daily Briefing**:

1. **Enable/disable** the daily briefing for your account
2. **Select your timezone** (overrides the server default)
3. **Set your preferred delivery time** (overrides the server default)
4. **Choose included sections** (see table above)

Email is the only delivery channel currently supported for the daily briefing.

## Troubleshooting

### "I'm not receiving the briefing"

1. **Check the scheduler** — is it running? `docker compose ps scheduler`
2. **Check SMTP settings** — can you send a test email? Run `docker compose exec app php artisan tinker` then `Mail::raw('test', fn($m) => $m->to('you@example.com')->subject('test'));`
3. **Check the logs** — `docker compose logs scheduler | grep briefing`
4. **Check the queue** — ensure Horizon is running: `docker compose ps horizon`
5. **Verify the time** — does `DAILY_BRIEFING_TIME` match your local time, taking `DAILY_BRIEFING_TIMEZONE` into account?
6. **Verify the schedule** — the job runs every minute and picks up users whose time matches the current server time in their configured timezone. If your timezone differs from the server's UTC, the comparison should still work as long as `DAILY_BRIEFING_TIMEZONE` is set correctly.

### "The briefing content looks wrong or confusing"

- The AI provider used for the briefing may differ from your chat provider. Check `DAILY_BRIEFING_PROVIDER` and `DAILY_BRIEFING_MODEL`.
- Some sections may be empty if there's no data (e.g., no calendar connection, no tasks).
- Try regenerating: toggle the briefing off and on in **Settings → Daily Briefing**.

### "Calendar events are missing from the briefing"

- Verify that Google Calendar is connected and authorised: **Settings → Integrations → Google Calendar**.
- Ensure the calendar connection status is "Connected" and not expired.
- Check the OAuth token hasn't expired — reconnect if needed.
